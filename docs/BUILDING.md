## How it works

1. `tools/pe/analyze_pe.py` read the game's Windows binary (`LEGOHarryPotter.exe`, PE32, x86) once and wrote its functions and switch tables to `recon/`. Those files are committed, and they describe only the one Steam build whose sha256 `setup.sh` checks.
2. `engine/` is the MacRecomp engine, a git submodule. Its lifter (`engine/tools/xrecomp/`) translates every x86 function into C. `tools/pe/run_lift_pe.py` runs it on the PE image with `recon/analysis.json`. The output goes to `generated.nosync/`: 45,882 functions in 92 files, none left as stubs. It is never committed.
3. `runtime/` replaces what Windows gives the game: the loader and the 231 imports from 14 DLLs. See [The Win32 layer](#the-win32-layer).
4. `build/Makefile` compiles the lifted C, the engine's generic runtime (guest memory, guest calls, heap, diagnostics, overlay text) and `runtime/` into `build.nosync/lhp`.
5. `make -C build app` packages it as `build.nosync/Wizard Bricks Recompiled.app` with every non-system library inside it (`tools/package/make_app.sh`). The app icon is taken from your copy of the game exe at build time.

At run time `lhp` maps the original exe into guest memory, binds its imports to the runtime, and runs the lifted entry point. It reads the game's data files from the Steam folder and never writes there.

Guest memory reads and writes use ordered arm64 loads and stores (`TSO=1`), so threads see memory in x86 order.

## The Win32 layer

`runtime/src/` holds one file per group of imports ("slice"), all built on the engine runtime:

| Area | Files | Built on |
|---|---|---|
| Loader and start-up | `pe_load.c`, `hp_boot.c`, `hp_boot_main.c` | the engine's guest memory |
| Kernel: files, memory, threads, sync, time | `win32_core.c`, `win32_fs.c`, `win32_mem.c`, `win32_sync.c` | POSIX and pthreads |
| Windows, messages, display | `win32_ui.c` | SDL2 |
| Keyboard and gamepad (DirectInput 8, XInput) | `win32_input.c` | SDL2 |
| Audio (XAudio2, X3DAudio) | `win32_xaudio2.c`, `win32_audio.c` | FAudio |
| COM and network | `win32_com.c`, `com_guest.c`, `win32_net.c` | |
| Direct3D 9 | `gen_d3d9_guest.c` (generated by `tools/d3d9/gen_d3d9_guest.py`), `d3d9_guest_manual.c`, `d3d9_backend.c` | DXVK Native on Vulkan, with KosmicKrisp (Vulkan on Metal) |
| D3DX 9 (shader compile, textures) | `d3dx_shader.c`, `d3dx_misc.c` | vkd3d-shader |
| Imports no slice implements | `win32_unsupported.c` (generated by `tools/win32/emit_unsupported_stubs.py`) | logs `UNSUPPORTED` and the import name once, then returns 0 |
| Game patches, overlay, tracing, scripted input | `hp_patches.c`, `hp_hud.c`, `frame_trace.c`, `input_script.c`, `hp_nav.c` | |

`hp_main.c` is an older load-only driver. It is not part of the game build.

`docs/WIN32_THUNKS.md` is the calling contract. `notes/win32_imports.md` lists every import and its slice.

## Graphics libraries (tools/deps)

Three scripts build pinned, patched copies of the graphics libraries. `setup.sh` runs them, and each skips the steps already done:

- `tools/deps/build_dxvk.sh`: DXVK Native, Direct3D 9 only, SDL2 window system, with the patches in `tools/dxvk_test/patches/`.
- `tools/deps/build_vkd3d.sh`: vkd3d-shader, with the patch in `tools/vkd3d/patches/`.
- `tools/deps/build_kosmickrisp.sh`: the KosmicKrisp Vulkan driver from Mesa, with the patches in `tools/package/patches/`. This build is the long one.

They install into `build.nosync/deps/` (set `HPRECOMP_DEPS_DIR` to use another folder). `tools/deps/README.md` lists the source pins and the Homebrew packages each one needs. SDL2, SDL3, FAudio and the Vulkan loader come from Homebrew as they are.

## Build by hand

```sh
git submodule update --init
python3 -m venv .venv
.venv/bin/pip install capstone

mkdir -p orig.nosync
cp "<game folder>/LEGOHarryPotter.exe" orig.nosync/lhp_win32.exe
shasum -a 256 orig.nosync/lhp_win32.exe   # must be 21c2d30c...16e3, as in setup.sh

tools/deps/build_dxvk.sh
tools/deps/build_vkd3d.sh
tools/deps/build_kosmickrisp.sh

.venv/bin/python -I tools/pe/run_lift_pe.py --engine engine \
    --analysis recon/analysis.json --switch recon/switch_tables.json \
    --bin orig.nosync/lhp_win32.exe --out generated.nosync --prefix lhp --jobs 8
make -C build -j8                                      # build.nosync/lhp
make -C build app HP_GAME_DIR="<game folder>"          # build.nosync/Wizard Bricks Recompiled.app
```

`make` tracks headers, `OPT`, `TSO`, `ENGINE` and `GEN`, but not other flags. After you change another flag, delete `build.nosync/obj/` before you build again. `make -C build OPT=1` compiles faster and runs slower.

Build outside `~/Documents`. iCloud adds Finder attributes to bundle folders there, and then `codesign --verify --strict` fails.

## Options

The app's launcher (`Contents/MacOS/HarryPotterRecompiled`) reads these:

| Variable | Effect |
|---|---|
| `HPRECOMP_GAME_DIR=<path>` | The folder with `LEGOHarryPotter.exe` and `GAME*.DAT`, if it moved since the build |
| `HPRECOMP_EXE=<path>` | The game image (`orig.nosync/lhp_win32.exe` by default) |
| `HPRECOMP_WINDOWED=1` | A window the size of the back buffer, instead of a borderless desktop-sized window |
| `HPRECOMP_FULLSCREEN=1` | The game's exclusive fullscreen (a display mode switch) |
| `RECOMP_HUD=1` | Show the frame-time overlay at start (Cmd+F toggles it) |
| `RECOMP_ASSUME_FOCUS=1` | Treat the window as focused. Use this for runs started by a script |
| `RECOMP_NO_ALERT_UI=1` | Print errors to the log instead of showing a dialog |

Saves go to `~/Library/Application Support/HarryPotterRecomp/` and logs to `~/Library/Logs/HarryPotterRecomp/` (the newest 20 runs). `notes/packaging.md` has the display details.

## Tests

```sh
tests/run_all.sh --engine engine            # every runtime test; or: make -C build test
tests/run_all.sh --engine engine --no-gpu   # leave out the tests that need a GPU
.venv/bin/python -m pytest -q tests tools   # the Python tools (needs pytest in the venv)
```

`tests/run_all.sh` builds each test from `tests/test_*.c` with only the files it needs, and prints one PASS, FAIL or SKIP line per test. A test that needs game data skips when it is absent. It links DXVK, vkd3d-shader and KosmicKrisp from `HPRECOMP_DEPS_DIR` (default `build.nosync/deps`), so run `setup.sh` once first.

## Repository layout

| Path | Contents |
|---|---|
| `setup.sh` | One-command setup: checks, graphics libraries, translation, build, app |
| `engine/` | The MacRecomp engine (submodule): lifter and generic runtime |
| `recon/` | The committed analysis of the game binary |
| `runtime/` | The Win32 layer and the boot driver (`include/` and `src/`) |
| `build/Makefile` | The game build and the `app` and `test` targets |
| `tools/deps/` | Builds DXVK, vkd3d-shader and KosmicKrisp |
| `tools/package/` | `make_app.sh`, the launcher, `Info.plist` and the icon extractor |
| `tools/pe/` | PE analysis, names and the lift driver |
| `tools/d3d9/`, `tools/win32/` | Generators for the D3D9 thunks and the unsupported-import stubs |
| `tools/boot/`, `tools/check/`, `tools/perf/`, `tools/trace/`, `tools/shaders/` | Boot runs, reliability checks, frame-time reports, import traces, shader tools |
| `tests/` | Runtime tests (C) and tool tests (Python) |
| `docs/`, `notes/` | Plans, contracts and investigation notes |
| `orig.nosync/`, `generated.nosync/`, `build.nosync/` | Your game binary, the lift output and the build output (never committed) |
