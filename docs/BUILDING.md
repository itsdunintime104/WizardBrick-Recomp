## How it works

1. `engine/windows/tools/pe/analyze_pe.py` read the game's Windows binary (`LEGOHarryPotter.exe`, PE32, x86) once and wrote its functions and switch tables to `recon/`. Those files are committed, and they describe only the one Steam build whose sha256 `setup.sh` checks.
2. `engine/` is the MacRecomp engine, a git submodule. Its lifter (`engine/tools/xrecomp/`) translates every x86 function into C. `engine/windows/tools/pe/run_lift_pe.py` runs it on the PE image with `recon/analysis.json`. The output goes to `generated.nosync/`: 45,882 functions in 92 files, none left as stubs. It is never committed.
3. The engine's Windows runtime (`engine/windows/runtime/`) replaces what Windows gives the game: the loader and the 231 imports from 14 DLLs. See [The Win32 layer](#the-win32-layer). This repo's `runtime/` holds only the HP code: game patches, scripted menu input and the shader cache warm-up.
4. `build/Makefile` sets the HP sources and settings and includes the engine's build rules (`engine/windows/build/game.mk`). They compile the lifted C, the engine's generic runtime (guest memory, guest calls, heap, diagnostics, overlay text), the Windows runtime and `runtime/` into `build.nosync/lhp`. The names (app, bundle id, save folder) come from `game.conf`.
5. `make -C build app` packages it as `build.nosync/LEGO Harry Potter Years 1-4.app` with every non-system library inside it (`engine/windows/tools/package/make_app.sh`). The app icon is taken from your copy of the game exe at build time.

At run time `lhp` maps the original exe into guest memory, binds its imports to the runtime, and runs the lifted entry point. It reads the game's data files from the Steam folder and never writes there.

Guest memory reads and writes use ordered arm64 loads and stores (`TSO=1`), so threads see memory in x86 order.

## The Win32 layer

`engine/windows/runtime/src/` holds one file per group of imports ("slice"), all built on the engine runtime. The engine's `windows/README.md` describes the interface a game repo uses.

| Area | Files | Built on |
|---|---|---|
| Loader and start-up | `pe_load.c`, `pe_boot.c`, `pe_boot_main.c` | the engine's guest memory |
| Kernel: files, memory, threads, sync, time | `win32_core.c`, `win32_fs.c`, `win32_mem.c`, `win32_sync.c` | POSIX and pthreads |
| Windows, messages, display | `win32_ui.c` | SDL2 |
| Keyboard and gamepad (DirectInput 8, XInput) | `win32_input.c` | SDL2 |
| Audio (XAudio2, X3DAudio) | `win32_xaudio2.c`, `win32_audio.c` | FAudio |
| COM and network | `win32_com.c`, `com_guest.c`, `win32_net.c` | |
| Direct3D 9 | `gen_d3d9_guest.c` (generated by `engine/windows/tools/d3d9/gen_d3d9_guest.py`), `d3d9_guest_manual.c`, `d3d9_backend.c` | DXVK Native on Vulkan, with KosmicKrisp (Vulkan on Metal) |
| D3DX 9 (shader compile, textures) | `d3dx_shader.c`, `d3dx_misc.c` | vkd3d-shader |
| Imports no slice implements | `win32_unsupported.c` (generated by `engine/windows/tools/win32/emit_unsupported_stubs.py`) | logs `UNSUPPORTED` and the import name once, then returns 0 |
| Overlay, tracing, scripted input | `d3d9_hud.c`, `frame_trace.c`, `input_script.c` | |

This repo's `runtime/src/` adds the HP files: `hp_patches.c` (game patches keyed by guest call site), `hp_nav.c` (scripted menu input) and `hp_warm.c` (the shader cache warm-up, `HPRECOMP_WARM_SHADERS=1`). They use the hooks in `engine/windows/runtime/include/game_hooks.h`.

`docs/WIN32_THUNKS.md` is the calling contract. `notes/win32_imports.md` lists every import and its slice.

## Graphics libraries

Three scripts in `engine/windows/tools/deps/` build pinned, patched copies of the graphics libraries. `setup.sh` runs them, and each skips the steps already done:

- `build_dxvk.sh`: DXVK Native, Direct3D 9 only, SDL2 window system, with the patches in `engine/windows/tools/dxvk_test/patches/`.
- `build_vkd3d.sh`: vkd3d-shader, with the patch in `engine/windows/tools/vkd3d/patches/`.
- `build_kosmickrisp.sh`: the KosmicKrisp Vulkan driver from Mesa, with the patches in `engine/windows/tools/package/patches/`. This build is the long one.

They install into `build.nosync/deps/` (set `HPRECOMP_DEPS_DIR` to use another folder). `engine/windows/tools/deps/README.md` lists the source pins and the Homebrew packages each one needs. SDL2, SDL3, FAudio and the Vulkan loader come from Homebrew as they are.

## Build by hand

```sh
git submodule update --init
python3 -m venv .venv
.venv/bin/pip install capstone

mkdir -p orig.nosync
cp "<game folder>/LEGOHarryPotter.exe" orig.nosync/lhp_win32.exe
shasum -a 256 orig.nosync/lhp_win32.exe   # must be 21c2d30c...16e3, as in game.conf

D=build.nosync/deps
for d in dxvk vkd3d kosmickrisp; do engine/windows/tools/deps/build_$d.sh $D/$d-work $D/$d; done

.venv/bin/python -I engine/windows/tools/pe/run_lift_pe.py --engine engine \
    --analysis recon/analysis.json --switch recon/switch_tables.json \
    --bin orig.nosync/lhp_win32.exe --out generated.nosync --prefix lhp --jobs 8
make -C build -j8                                      # build.nosync/lhp
make -C build app GAME_DIR="<game folder>"             # build.nosync/LEGO Harry Potter Years 1-4.app
engine/windows/tools/package/check_app.sh "build.nosync/LEGO Harry Potter Years 1-4.app"
```

`make` tracks headers, `OPT`, `TSO`, `ENGINE` and `GEN`, but not other flags. After you change another flag, delete `build.nosync/obj/` before you build again. `make -C build OPT=1` compiles faster and runs slower.

Build outside `~/Documents`. iCloud adds Finder attributes to bundle folders there, and then `codesign --verify --strict` fails.

## Options

The app's launcher (`Contents/MacOS/HarryPotterRecompiled`) reads these:

| Variable | Effect |
|---|---|
| `HPRECOMP_GAME_DIR=<path>` | The folder with `LEGOHarryPotter.exe` and `GAME*.DAT`, if it moved since the build |
| `HPRECOMP_EXE=<path>` | The game image (`orig.nosync/lhp_win32.exe` by default) |
| `HPRECOMP_WINDOWED=1` | A window the size of the back buffer, instead of a borderless desktop-sized window |
| `HPRECOMP_FULLSCREEN=1` | The game's exclusive fullscreen (a display mode switch) |
| `RECOMP_HUD=1` | Show the frame-time overlay at start (Cmd+F toggles it) |
| `RECOMP_ASSUME_FOCUS=1` | Treat the window as focused. Use this for runs started by a script |
| `RECOMP_NO_ALERT_UI=1` | Print errors to the log instead of showing a dialog |

Saves go to `~/Library/Application Support/HarryPotterRecomp/` and logs to `~/Library/Logs/HarryPotterRecomp/` (the newest 20 runs). `notes/packaging.md` has the display details.

## Tests

```sh
make -C build test                          # the engine's Windows runtime tests and the HP tests
make -C build test TEST_ARGS=--no-gpu       # leave out the tests that need a GPU
.venv/bin/python -m pytest -q tests tools   # the Python tools (needs pytest in the venv)
```

`make test` runs `engine/windows/tests/run_all.sh --tests tests/game_tests.sh`. It builds each C test with only the files it needs, and prints one PASS, FAIL or SKIP line per test. A test that needs game data skips when it is absent. It links DXVK, vkd3d-shader and KosmicKrisp from `HPRECOMP_DEPS_DIR` (default `build.nosync/deps`), so run `setup.sh` once first.

## Repository layout

| Path | Contents |
|---|---|
| `setup.sh` | One-command setup: runs `engine/windows/setup.sh` (checks, graphics libraries, translation, build, app) |
| `game.conf` | The game's names, exe file name and sha256, lift inputs and the shader warm-up step, read by `setup.sh` and `build/Makefile` |
| `engine/` | The MacRecomp engine (submodule): lifter, generic runtime, and in `windows/` the Win32 and D3D9 runtime, the PE tools, the runtime tests, the build rules and the setup script |
| `recon/` | The committed analysis of the game binary |
| `runtime/` | The HP code: game patches, scripted menu input, shader cache warm-up (`include/` and `src/`) |
| `build/Makefile` | The HP sources and settings; the rules and the `app` and `test` targets come from `engine/windows/build/game.mk` |
| `tools/boot/`, `tools/check/`, `tools/trace/`, `tools/shaders/`, `tools/d3d9_caps/` | Boot runs, reliability checks, import traces, shader tools, a D3D9 device probe |
| `tests/` | HP tests (C and Python) and `game_tests.sh`, their list for the engine's `run_all.sh` |
| `docs/`, `notes/` | Plans, contracts and investigation notes |
| `orig.nosync/`, `generated.nosync/`, `build.nosync/` | Your game binary, the lift output and the build output (never committed) |
